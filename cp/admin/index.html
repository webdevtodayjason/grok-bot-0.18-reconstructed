Every refusal and every lockout at both doors, from the console and from this service. The password that was tried is never kept. What is kept is a keyed hash of it, which is enough to say whether it was the same password again or a different one, and nothing else.

Providers, keys and plan models

Who supplies the models, which keys open them, and what each plan runs on. Nothing on this page needs a restart. What it does need is a moment: the proxy picks a change up on the next request, a workspace on its next turn, and a customer's open page the next time that page loads.

Providers and their keys

The short name is what every key on this provider is named after, so zai gives zai-1 and zai-2, and it is on every spend row from then on. Kind is the shape of the API this provider speaks, which is nearly always openai. Address is the base the requests go to. The model list path is where the provider publishes what it serves, if it does: leave it empty and the Refresh button stays off and the list stays the one we keep ourselves. Add the provider first, then add a key to it, then point a plan model at that key.

Plan models

One row per model a plan includes. The name and the label are what a customer reads and what their Titan says it runs on. The vendor model underneath is the thing that changes when a provider retires one, and changing it leaves the customer's workspace pointed at the same place.

The routing name is what a workspace is pointed at. It is set once and never changed after, because every workspace already running on it names it.

Feedback

Every report here was written by an agent, shown to the workspace operator, and sent by that person. This is the second gate.

Where an issue gets filed

GitHub is asked whether it takes this token for that repository before anything is stored, and a token it refuses is not kept. Nothing on this page ever shows the value again: what comes back is a length and eight characters of a digest. This token stays on this service and is never pushed into a customer's box.
